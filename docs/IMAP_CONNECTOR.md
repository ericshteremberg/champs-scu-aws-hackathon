# IMAP mailbox connector

Causality supports a customer-configured IMAP mailbox through Connections → Other email provider. Network Solutions customers can use this path without a Google account, developer registration or custom endpoint. The implementation also accepts other public IMAP servers that support mailbox/app-password authentication and implicit TLS on port 993. Provider compatibility is not the same as a completed customer test. No real mailbox has been connected or read during implementation.

## Customer setup

1. Open [Connections](https://causality-hackathon-dev.slidah60.workers.dev/workspace?view=integrations) and choose **Connect other email**.
2. Enter the full mailbox email and the exact incoming IMAP hostname from the provider. Do not enter a URL or port. Network Solutions has several email platforms; get the settings for the actual account using its [official setup guide](https://www.networksolutions.com/help/article/how-do-i-get-started-with-pop3-and-imap). The app deliberately does not guess a hostname from the email domain.
3. Enter a mailbox password or provider-issued app password directly in the form. Prefer an app password where supported. Keep credentials out of chat, screenshots and Git. A credential may authorize more operations than Causality performs.
4. INBOX is included. Optionally add the exact Sent folder name to find outgoing replies. Folder names can differ between providers. Both folders must be accessible for the connection check to pass; no folders are created or renamed.
5. Review the storage/read-access notice, check the authorization box and click **Test and connect mailbox**. Causality verifies TLS, login and read-only folder access before saving credentials. It does not fetch message bodies during setup. Failed checks do not retain the password; the input clears after submission. Repeated login attempts are limited to one per 30 seconds per workspace.
6. Choose an open case and **Find customer emails via IMAP**. Search is derived from the case customer's email; it checks the newest 500 messages per selected folder and returns up to ten matching headers. It checks exact From/To envelope addresses after the server's substring search. It is not a full mailbox audit or a proof of order relevance.
7. Preview a result, review its plain text and case, then **Import reviewed IMAP email**. Import invalidates prior draft approval and makes the previous investigation stale. Run a new investigation when appropriate. Nothing is sent to the customer or submitted to Stripe.
8. **Disconnect IMAP** removes saved credentials and prevents subsequent reads/imports. A request already in flight can finish its network read until its deadline, but cannot save its result after disconnect. Revoke any app password with the provider separately. Imported case evidence remains.

Use the Gmail OAuth connector for Google-hosted mail. Microsoft 365 OAuth, custom ports, plaintext/STARTTLS, non-email usernames, delegated accounts and local-only servers are not supported by this IMAP form. Proton Bridge is not a public hosted mailbox endpoint for this deployment.

## Runtime and data flow

- `components/workspace/imap-provider.tsx` handles setup, explicit access confirmation, case selection, preview/import and disconnect. Passwords exist only in transient form/request memory, never localStorage or sessionStorage. The hosted preview uses the existing shared team login; all people using that login share its connections and imported evidence.
- Same-origin POST `/api/providers/imap` goes through the authenticated Cloudflare bridge to private AWS Lambda. Supported actions are `connect`, `disconnect`, `search`, `preview`, and `import`. No new Cloudflare storage is introduced. The local non-AWS route returns `aws_required`.
- `aws/imap-provider.ts` validates strict action schemas, requires workspace ownership and mutable cases, and applies version-conditional DynamoDB transactions. Connection attempts reserve a version before network I/O, so concurrent disconnect or setup cannot restore an old connection.
- Public metadata is projected from `provider#imap`. Login settings/password are stored separately in `provider-token#imap` under the workspace partition, using the existing DynamoDB encryption at rest and IAM-protected backend. This is not a per-mailbox Secrets Manager secret or separate application-layer encryption. Passwords are absent from status, workspace, audit, evidence and model inputs. Network protocol logging is disabled and provider errors are sanitized.
- `imap-selection#<caseId>` and `imap-preview#<caseId>` hold temporary, case- and connection-version-bound results with ten-minute TTLs. Expiry is enforced before use; DynamoDB physical deletion can take longer. Only IDs in a current search may be previewed. Import uses the exact server-held preview, not client-provided content.
- `aws/imap-api.ts` uses ImapFlow and MailParser only inside Lambda. The hostname resolves on every operation; any private, loopback, link-local, platform, mixed or reserved answer is rejected using the existing public-address policy. The TCP connection is pinned to the validated IPv4 address while TLS verifies the original hostname. Only TLS 1.2+ on port 993 is allowed, with no certificate bypass or proxy.
- Each operation has a 16-second total deadline, shorter connection/greeting/inactivity timeouts, bounded protocol lines/literals and response sizes, and closes its connection when finished. Folders use EXAMINE (`readOnly: true`); source reads use BODY.PEEK. No send, flag, delete, move, append or expunge operations are exposed.
- Message identity includes folder, UIDVALIDITY and UID. Preview verifies UIDVALIDITY and bounds the raw source to 256 KiB before parsing. HTML-to-text conversion and remote-image processing are disabled. HTML and attachments, including attached forwarded messages, are excluded from evidence; text in the actual inline body is retained. Plain-text excerpts are capped at 20,000 characters and labeled when truncated. Credential echoes in returned data fail closed.
- Imported evidence has `source: imap`, its source identity and mailbox/folder/header provenance. The investigation maps it to support evidence. Stable host/mailbox/folder/UIDVALIDITY/UID identity prevents duplicate imports into the same case. Aliases or a server UID reset can result in a different identity; this is not content-based deduplication.

## Verification and remaining test

Backend tests cover public-address filtering, DNS changes, TLS hostname preservation, read-only access, exact email matching, response bounds, MIME exclusions, deadlines, secret privacy, login throttling, disconnect races, workspace isolation, stale selections, reviewed-content import, duplicate rejection and approval invalidation. UI tests cover setup consent, password clearing, mobile layout, case selection, inert message text, preview-before-import and disconnect.

The remaining customer acceptance test is Eric's real Network Solutions login, exact folder names, a real case search, one reviewed import and disconnect. No credentials are preinstalled. Other providers also need compatibility testing before being advertised as verified. Background synchronization, paging through older mail, attachments, multiple simultaneous IMAP mailboxes per workspace, production team membership and evidence-retention deletion remain separate work.
