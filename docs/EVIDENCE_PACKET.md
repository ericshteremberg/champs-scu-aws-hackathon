# Evidence packet and review boundary

## Customer flow

1. Collect, inspect, and attach the relevant provider evidence to the case. Connector previews that have not been attached are not included.
2. Run the investigation or prepare an evidence template. AWS investigations first collect original Stripe receipts, approved Supabase query results and available case-linked Resend email bodies. **Collect original evidence** on Report can retry this separately. New captures invalidate prior approval and require a fresh investigation before PDF export.
3. Open Report and download the evidence PDF. Draft copies are explicitly labeled for review. Save any response edits first.
4. Optionally approve the saved revision to record merchant review. Downloading, approval and S3 archival never submit to Stripe.

Report preview and Review package use the same saved response and complete source index. Internal review notes remain in the workspace and are not exported. The factual narrative must retain material qualifications and contradictions beside the affected claims. No automatic removal of adverse statements occurs.

## Implementation

- `lib/report/packet.ts`: stable source numbering, readable citations, complete source inclusion, legacy diagnostic separation, internal review notes and export preconditions.
- `lib/report/pdf.ts`: lazy-loaded PDF generation using pdf-lib and fontkit. Embedded Liberation Sans regular/bold fonts use the SIL Open Font License (`public/fonts/LICENSE_LIBERATION`), distributed with Mozilla pdfjs-dist. The report follows the reference's Helvetica-style typography, black numbered headings, gray claim panel and thin rules. App-created report and query-result visuals use grayscale; original evidence files retain their original appearance and bytes. All fonts load from this app's origin.
- `aws/original-evidence.ts`: bounded, read-only provider capture before the investigation snapshot. Recipient, exact order, sender and workspace must match. Captured provider fields and original HTML/text are retained in immutable private S3 objects with collection timestamps and SHA-256 fingerprints. Existing sources are never replaced by an invented reconstruction.
- `aws/capture-originals.ts`: coordinates Stripe, Supabase and Resend collection in order, since each successful collector advances the case revision. Provider failures remain independent and explicit.
- `aws/stripe-originals.ts` and `aws/stripe-receipt-file.ts`: verify the connected dispute, charge, account, amount and exact order before following the charge's hosted receipt and its actual Download receipt link. Only approved Stripe HTTPS hosts are allowed at every redirect. OAuth credentials are never forwarded to file hosts. Original PDF bytes are kept, not regenerated from charge descriptions. This uses charge-read access and does not require invoice-read access.
- `aws/supabase-originals.ts`: preserves original returned rows, query, parameters and source metadata under the customer's approved mapping. No model prose is converted into original evidence. Direct payment-linked order, ticket, delivery, attendance and support queries are supported. A limited fallback reuses approved ID/name/email fields for exact IDs from verified charge metadata, requiring the case email to match. Additional columns are never silently approved. Changed rows produce a new snapshot; unchanged rows deduplicate.
- `lib/report/row-renderer.ts`: visually renders exact database values as a query-result export, with the original JSON also attached. It does not imitate the provider dashboard. Values are canvas text, never executable HTML. Source counts, query limits and omitted/unapproved columns remain explicit.
- `lib/report/exhibits.ts`: downloads only authorized case-file endpoints, verifies byte fingerprints and enforces file limits. Failed retrieval or mismatched bytes stop the export instead of silently omitting a promised exhibit.
- `lib/report/email-renderer.ts`: DOMPurify and an isolated, script-disabled iframe render the retained provider body through html2canvas. Scripts, remote images, links and external stylesheets cannot execute or load. Visuals are labeled rendered original email content, not provider-dashboard screenshots.
- `components/workspace/evidence-packet.tsx`: shared preview. The PDF renderer independently paginates content, avoiding browser print controls, URLs and clipped textareas.
- `lib/investigation/sections.ts`: case-local topic routing. Matching words route evidence but never assert a fact. Provenance-defined sections are retained. Combined unclassified documents can cover more than one topic.

The PDF uses Letter pages, 48-point margins, repeated headers, page numbers, source IDs and UTC timestamps. There is no fixed page, word or evidence-count limit. The response consolidates repetition, while every factual source remains indexed and available in the packet. Long references wrap within margins. Font-unsupported characters are preserved as explicit Unicode code point notation with a typography note. Original exhibits are not duplicated as extracted-text appendix entries. Sources without visual originals retain their complete saved text in a compact appendix. Uncited manual records explicitly labeled Analyst review remain internal; factual manual records and any cited or attached originals remain included. Internal review-note pages and repeated provenance checklists are omitted. Original PNG/JPEG images, PDF pages and captured provider email bodies appear as visual exhibits. Long images split across pages at readable width. Original bytes are also embedded as file attachments, including the unmodified retained email snapshot. Signed download URLs and credentials are not included.

Each visual identifies its source, collection time when known, retrieval time and SHA-256. A hash detects byte changes, not whether the depicted content is authentic. Older uploads without a collection fingerprint are explicitly labeled. Text-only records remain text-only. Other file formats stay accessible in the case. Limits: 20 original files, 10 MB each, 40 MB total including rendered email images, 20 megapixels per image, 50 pages per source PDF and 100 visual exhibit pages. Fillable source PDFs require a separate flattened visual copy. PDF page annotations are not rendered; the embedded original retains them for inspection.

Automatic email capture covers explicitly linked Resend messages, up to three pending messages per attempt, with additional messages reported for a retry. Approved order-linked database message logs can supply email IDs in the same collection pass. A retained query result can establish the order link for a reminder that omits the order number, but live sender and exact recipient checks still apply. Manual prose cannot grant this exception. A missing historical body is not proof of retention expiry or non-delivery. Gmail/IMAP imports still provide their existing text evidence; automatic original-body capture is not yet implemented for those connectors.

Original receipt PDFs appear directly as nearly full-page reproductions with compact source metadata, without a separate cover. Structured database exports follow as visual exhibits. With no originals, the report explicitly says its export will be a text-only review draft. No synthetic image is substituted for a missing original.

The response reflects the saved case revision. Export requires a saved, current draft and all cited sources. It does not approve, persist, call a model or provider, or claim that available sources prove delivery or attendance. Existing historical drafts are not silently rewritten. Reinvestigation updates the narrative and review metadata. The investigator addresses the actual allegation, leads with the strongest sources, and covers every materially distinct relevant record without a fixed word or evidence-count limit. Quotes must be verbatim from retrieved sources. Internal advice, speculative admissions, unrelated charges and outcome predictions are excluded. Sample-mode drafts use a labeled inventory of all records, prioritizing failed delivery and acknowledgements. Model responses containing internal strategy/checklist language receive corrective feedback; material qualifications remain required.

## Disabled submissions

`aws/stripe.ts` and `lib/stripe/service.ts` unconditionally reject submission with HTTP 409 and `submission_disabled`. Both report `submissionEnabled: false`. The old environment flag cannot override the restriction. Stripe update calls were removed from both services. Read/sync and webhook ingestion remain available.
